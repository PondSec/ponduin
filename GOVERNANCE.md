# Ponduin governance

Ponduin is developed and maintained by PondSec.

## Product ownership

PondSec owns the Ponduin product direction, brand, release process and technical
roadmap. Product decisions are made by the designated PondSec maintainers.

## Branches and releases

- `dev` is the integration branch for active development.
- `main` contains releases that have completed product testing and approval.
- Changes reach `main` only after validation on `dev`.
- Release artifacts must be built from a reviewed and reproducible commit.

## Change control

Every change must:

1. have a clear, bounded purpose;
2. preserve security and privacy expectations;
3. include proportionate tests;
4. pass formatting, linting, build and test checks;
5. receive approval from a designated maintainer before release.

Changes that affect data handling, authentication, permissions, local execution
or external integrations require explicit security review.

## Maintainers

Maintainers are appointed by PondSec. They are responsible for:

- technical direction and architecture;
- code and dependency review;
- release quality;
- vulnerability response;
- compatibility and migration decisions;
- protecting the Ponduin brand and product experience.

## Licensing and third-party components

Product governance does not replace the licensing terms that apply to individual
source files or third-party components. The repository's `LICENSE` file and
component-specific license notices remain authoritative for those materials.
